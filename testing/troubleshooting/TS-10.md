# TS-10 — SNMP monitoring cannot detect a device

_Run 2026-11-08 22:03 UTC on the namespace emulation._

**Fault injected:** BR-R2's SNMP agent restarted with a different SNMPv3 auth key (credential mismatch between NMS and device).

## Symptom

```
$ snmpget -v3 -l authPriv -u monitor -a SHA -A <SNMP_AUTH> -x AES -X <SNMP_PRIV> -t 1 -r 0 192.168.199.1 SNMPv2-MIB::sysName.0
snmpget: Authentication failure (incorrect password, community or key)
```

## Diagnosis

```
$ ping -c 1 -W 1 192.168.199.1
PING 192.168.199.1 (192.168.199.1) 56(84) bytes of data.
64 bytes from 192.168.199.1: icmp_seq=1 ttl=63 time=0.120 ms

--- 192.168.199.1 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 0.120/0.120/0.120/0.000 ms
```

```
$ bash -c ip netns exec br-r2 ss -ulpn | grep ':161'
UNCONN 0      0      192.168.199.1:161        0.0.0.0:*    users:(("snmpd",pid=18723,fd=7))    
```

The device is reachable and snmpd listens on 161/udp, but the NMS reports an authentication failure. The v3 user's auth key differs between the device and the NMS.

## Fix

```
$ snmpget -v3 -l authPriv -u monitor -a SHA -A <SNMP_AUTH> -x AES -X <SNMP_PRIV> -t 1 -r 0 192.168.199.1 SNMPv2-MIB::sysName.0
SNMPv2-MIB::sysName.0 = STRING: BR-R2
```

## Outcome

**Root cause:** SNMPv3 auth key mismatch between device and NMS.

**Verified after fix:** PASS
