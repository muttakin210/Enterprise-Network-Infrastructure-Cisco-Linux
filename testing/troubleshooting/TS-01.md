# TS-01 — PC cannot reach its default gateway

_Run 2026-11-08 22:01 UTC on the namespace emulation._

**Fault injected:** ADMIN-PC's switch port (HQ-SW1 G0/1) moved to VLAN 20, as if someone typed `switchport access vlan 20` on the wrong port.

## Symptom

```
$ ip netns exec admin-pc ping -c 2 -W 1 192.168.10.1
PING 192.168.10.1 (192.168.10.1) 56(84) bytes of data.

--- 192.168.10.1 ping statistics ---
2 packets transmitted, 0 received, 100% packet loss, time 1021ms

```

## Diagnosis (show vlan brief / show interfaces switchport equivalent)

```
$ bridge -n hq-sw1 vlan show dev g0-1
port              vlan-id  
g0-1              20 PVID Egress Untagged
```

```
$ ip netns exec admin-pc ip neigh show
192.168.10.1 dev eth0 lladdr 3a:7b:44:6e:d0:08 REACHABLE
```

The port's PVID is 20, but the PC is addressed in VLAN 10, so its ARP requests for 192.168.10.1 are flooded in VLAN 20 and never answered.

## Fix

```
$ bridge -n hq-sw1 vlan show dev g0-1
port              vlan-id  
g0-1              10 PVID Egress Untagged
```

```
$ ip netns exec admin-pc ping -c 2 -W 1 192.168.10.1
PING 192.168.10.1 (192.168.10.1) 56(84) bytes of data.
64 bytes from 192.168.10.1: icmp_seq=1 ttl=64 time=0.091 ms
64 bytes from 192.168.10.1: icmp_seq=2 ttl=64 time=0.320 ms

--- 192.168.10.1 ping statistics ---
2 packets transmitted, 2 received, 0% packet loss, time 1009ms
rtt min/avg/max/mdev = 0.091/0.205/0.320/0.114 ms
```

## Outcome

**Root cause:** Access port in the wrong VLAN (PVID 20 instead of 10).

**Verified after fix:** PASS
