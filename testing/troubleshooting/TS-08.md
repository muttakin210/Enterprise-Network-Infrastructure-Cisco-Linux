# TS-08 — ACL blocks legitimate traffic

_Run 2026-11-08 22:03 UTC on the namespace emulation._

**Fault injected:** a deny for the Admin VLAN inserted at the top of FINANCE-PROTECT (wrong ACE order), as if `1 deny ip 192.168.10.0 0.0.0.255 any` were added.

## Symptom

```
$ ip netns exec admin-pc ping -c 2 -W 1 192.168.40.101
PING 192.168.40.101 (192.168.40.101) 56(84) bytes of data.

--- 192.168.40.101 ping statistics ---
2 packets transmitted, 0 received, 100% packet loss, time 1003ms

```

## Diagnosis (show access-lists — check hit counters and ordering)

```
$ ip netns exec br-r2 nft list chain ip cisco_acl finance_protect
table ip cisco_acl {
	chain finance_protect {
		ip saddr 192.168.10.0/24 counter packets 2 bytes 168 drop
		ip saddr 192.168.10.0/24 counter packets 8 bytes 672 accept
		ip saddr 192.168.50.10 counter packets 23 bytes 4972 accept
		ip saddr 192.168.20.0/24 counter packets 4 bytes 336 log prefix "BR-R2 FINANCE-PROTECT deny " drop
		ip saddr 192.168.30.0/24 counter packets 4 bytes 336 log prefix "BR-R2 FINANCE-PROTECT deny " drop
		counter packets 0 bytes 0 accept
	}
}
```

Rules are matched top-down. The new first rule drops Admin traffic before the intended `permit 192.168.10.0/24` is reached; its counter increments with each ping.

## Fix

```
$ ip netns exec admin-pc ping -c 2 -W 1 192.168.40.101
PING 192.168.40.101 (192.168.40.101) 56(84) bytes of data.
64 bytes from 192.168.40.101: icmp_seq=1 ttl=62 time=0.139 ms
64 bytes from 192.168.40.101: icmp_seq=2 ttl=62 time=0.139 ms

--- 192.168.40.101 ping statistics ---
2 packets transmitted, 2 received, 0% packet loss, time 1003ms
rtt min/avg/max/mdev = 0.139/0.139/0.139/0.000 ms
```

## Outcome

**Root cause:** Deny entry placed above the permit in FINANCE-PROTECT.

**Verified after fix:** PASS
